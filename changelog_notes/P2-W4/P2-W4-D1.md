### Changelog

#### 1. Create the GitHub Actions CI workflow

A GitHub Actions workflow was created at:

```text
.github/workflows/ci.yml
```

The workflow was designed to trigger when changes are pushed to `main` or when a pull request targets `main`.

The workflow currently performs:

```text
Git push / Pull Request
        |
        v
GitHub Actions
        |
        +-- Checkout repository
        +-- Set up Python 3.11
        +-- Verify Python version
        +-- Verify repository structure
        +-- Report CI validation success
```

The workflow configuration used was:

```yaml
name: Weather Intelligence Platform CI

on:
  push:
    branches:
      - main

  pull_request:
    branches:
      - main

jobs:
  ci:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"

      - name: Verify Python
        run: python --version

      - name: Verify repository structure
        run: |
          test -f Dockerfile
          test -d k8
          test -d orchestration
          test -d dags
          test -d w10_fastapi_service

      - name: CI validation successful
        run: echo "P2-W4-D1 CI validation passed"
```

#### 2. Commit and push the workflow

The workflow was committed to the `main` branch and pushed to GitHub.

The GitHub Actions workflow was then recognized by the repository and executed successfully.

#### 3. Verify the Git-based trigger

A harmless test file was created to generate a normal repository change and verify that a subsequent Git push would automatically trigger CI.

The file was:

```text

```

The initial attempt to commit the test change did not create a commit because the file was untracked and `README.md` had not actually been modified.

The repository reported:

```text
nothing added to commit but untracked files present
```

The test file was then correctly staged.

**Command**

```bash
git add test_README.md
```

The staged state was checked with:

```bash
git status
```

The output confirmed:

```text
Changes to be committed:

    new file: test_README.md
```
