# P2-W3 --- Daily Development Notes

## 31/08/2026

### Task

- P2-W3 D1: Deploy the consolidated Weather Intelligence Platform to the Oracle Cloud ARM64 K3s environment and establish the initial cloud deployment foundation.

### Changelog

#### 1. Prepare and verify the Oracle Cloud K3s environment

The Oracle Cloud VM was prepared as the cloud deployment environment for the Weather Intelligence Platform.

The environment used:

- Oracle Cloud VM
- Ubuntu 24.04
- ARM64 architecture
- K3s Kubernetes
- 2 GB swap
- `kubectl` configured for the `ubuntu` user

**Main Commands**

```bash
uname -m
free -h
kubectl get nodes
```

**Result**

```text
aarch64
```

```text
NAME                   STATUS   ROLES
weather-platform-k3s   Ready    control-plane
```

The Oracle VM was confirmed to be running as a Ready K3s control-plane node.

#### 2. Verify Kubernetes storage

K3s provides the `local-path` StorageClass for persistent workloads.

**Command**

```bash
kubectl get storageclass
```

**Result**

```text
NAME                   PROVISIONER
local-path (default)   rancher.io/local-path
```

This provided the storage foundation required for PostgreSQL and MinIO PersistentVolumeClaims.

#### 3. Transfer the consolidated Docker image to Oracle

The project uses the consolidated:

```text
airflow-custom:latest
```

Docker image containing Airflow, W1-W10, FastAPI, Dashboard and the orchestration code.

The existing ARM64 image was exported locally and transferred to the Oracle VM rather than rebuilding it on the VM.

**Main Local Command**

```bash
docker save airflow-custom:latest -o airflow-custom-latest.tar
```

#### 4. Import the Docker image into K3s containerd

K3s uses containerd, so the Docker image needed to be explicitly imported into the K3s image store.

**Oracle VM Command**

```bash
sudo k3s ctr images import airflow-custom-latest.tar
```

The first import attempt encountered containerd content-store errors because the containerd storage state was incomplete after the cleanup.

K3s was restarted to recreate the required containerd storage structure.

```bash
sudo systemctl restart k3s
```

The image was then imported successfully.

**Result**

```text
docker.io/library/airflow-custom:latest
```

The image was confirmed as a Linux ARM64 image and was successfully available to K3s.

#### 5. Deploy PostgreSQL and MinIO

PostgreSQL was deployed first because it is required by Airflow.

**Main Commands**

```bash
kubectl apply -f k8/postgres/pvc.yaml
kubectl apply -f k8/postgres/statefulset.yaml
kubectl apply -f k8/postgres/service.yaml
```

MinIO was then deployed with persistent storage.

```bash
kubectl apply -f k8/minio/pvc.yaml
kubectl apply -f k8/minio/statefulset.yaml
kubectl apply -f k8/minio/service.yaml
```

Both workloads were configured with PersistentVolumeClaims using the K3s `local-path` StorageClass.

#### 6. Deploy Airflow and application services

Airflow RBAC and the initialization Job were deployed before the Airflow services.

**Main Commands**

```bash
kubectl apply -f k8/airflow/rbac.yaml
kubectl apply -f k8/airflow/airflow-init.yaml
kubectl apply -f k8/airflow/api-server.yaml
kubectl apply -f k8/airflow/scheduler.yaml
kubectl apply -f k8/airflow/dag-processor.yaml
```

FastAPI and the Prediction Dashboard were subsequently deployed.

```bash
kubectl apply -f k8/fastapi/deployment.yaml
kubectl apply -f k8/dashboard/deployment.yaml
```

#### 7. Initial deployment problems

The initial deployment exposed several configuration issues:

- Kubernetes workloads reported `CreateContainerConfigError` because the `weather-env` Secret was not available to the newly deployed workloads.
- FastAPI and Dashboard init containers reported `Init:ErrImageNeverPull` because the AWS CLI image used by the init containers was configured with an unsuitable `imagePullPolicy`.
- The limited Oracle VM CPU resources later caused a FastAPI replacement pod to remain `Pending`.

These issues were investigated and resolved during the P2-W3 deployment and validation work.

The `weather-env` Secret was recreated from the VM copy of the project `.env` file:

```bash
kubectl create secret generic weather-env --from-env-file=/home/ubuntu/.env
```

The AWS CLI init containers were changed from `Never` to `IfNotPresent`, allowing Kubernetes to pull the required AWS CLI image.

### Observations

The main deployment challenge was the difference between the local Docker environment and K3s.

The local project image was built with Docker, while K3s uses containerd. Therefore, the existing ARM64 Docker image had to be explicitly imported into K3s.

The deployment also demonstrated that Kubernetes configuration problems such as missing Secrets, image pull policies and resource constraints must be resolved before the complete application can become Ready.

The Oracle VM successfully became the cloud Kubernetes environment for the consolidated Weather Intelligence Platform.

### Final Status

**P2-W3 D1: Complete**

The consolidated `airflow-custom:latest` ARM64 image was successfully transferred to Oracle Cloud and imported into K3s. PostgreSQL, MinIO, Airflow, FastAPI and Dashboard deployment foundations were established, and the initial Kubernetes configuration issues were identified and resolved.
