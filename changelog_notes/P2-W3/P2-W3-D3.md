# P2-W3 --- Daily Development Notes

## 02/09/2026

### Task

- P2-W3 D3: Establish persistent storage for PostgreSQL and MinIO and validate workload recovery in the Oracle Cloud K3s environment.

### Changelog

#### 1. Configure persistent storage

PostgreSQL and MinIO were deployed with Kubernetes PersistentVolumeClaims using the K3s `local-path` StorageClass.

**Main Commands**

```bash
kubectl get pvc

kubectl get pv

kubectl get storageclass
```

The PVCs were successfully bound:

```text
postgres-data    Bound    5Gi    RWO    local-path
minio-data       Bound    5Gi    RWO    local-path
```

Both workloads therefore had persistent storage rather than relying on container-local storage.

#### 2. Verify PostgreSQL persistence

The PostgreSQL StatefulSet used the `postgres-data` PVC and mounted it at:

```text
/var/lib/postgresql/data
```

The database was checked to confirm that Airflow metadata was present.

**Command**

```bash
kubectl exec postgres-0 -- psql -U airflow -d airflow -c "SELECT COUNT(*) FROM dag;"
```

The query returned an existing DAG record, confirming that PostgreSQL was operating correctly.

#### 3. Test pod recovery

A PostgreSQL pod deletion was used to test Kubernetes recovery:

```bash
kubectl delete pod postgres-0
```

Kubernetes recreated the StatefulSet pod.

The test demonstrated the distinction between deleting a pod and deleting its PersistentVolumeClaim: the pod is disposable, while the persistent data remains associated with the PVC.

MinIO was similarly deployed as a StatefulSet with its own PVC so that `/data` remained persistent across pod replacement.

### Problems Faced

The main challenge was understanding and validating the relationship between:

- StatefulSets
- PersistentVolumeClaims
- PersistentVolumes
- K3s `local-path` storage

The recovery test showed that application pods can be replaced by Kubernetes without intentionally removing the underlying persistent storage.

### Observations

The final storage configuration used:

- PostgreSQL: 5 GiB PVC
- MinIO: 5 GiB PVC
- Access mode: `ReadWriteOnce`
- StorageClass: `local-path`
- Reclaim policy: `Delete`

The PVs were backed by directories under the K3s local storage path on the Oracle node.

This provided the persistence foundation required for the cloud deployment.

### Final Status

**P2-W3 D3: Complete**

PostgreSQL and MinIO persistent storage was successfully configured and verified. PostgreSQL pod recovery was tested, and the Kubernetes StatefulSet/PVC configuration demonstrated that workload replacement does not inherently remove persistent application data.
