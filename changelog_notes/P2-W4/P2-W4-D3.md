### Changelog

#### 1. Configure GHCR publishing in GitHub Actions

The existing `.github/workflows/ci.yml` was extended with the
permissions and GHCR publishing steps required for D3.

The package permission added was:

``` yaml
permissions:
  contents: read
  packages: write
```

`packages: write` allows the GitHub Actions workflow to publish the
Docker image to GitHub Container Registry.

#### 2. Add GHCR authentication

The following step was added to the existing workflow:

``` yaml
- name: Log in to GitHub Container Registry
  if: github.event_name == 'push' && github.ref == 'refs/heads/main'
  uses: docker/login-action@v3
  with:
    registry: ghcr.io
    username: ${{ github.actor }}
    password: ${{ secrets.GITHUB_TOKEN }}
```

This logs the workflow into GHCR only for a push to `main`.

`GITHUB_TOKEN` is used instead of creating a separate registry password.

#### 3. Tag the image with the Git commit SHA

The Docker image already built by the CI workflow was given a
Git-SHA-based registry tag:

``` yaml
- name: Tag image with commit SHA
  if: github.event_name == 'push' && github.ref == 'refs/heads/main'
  run: |
    docker tag \
      weather-platform:ci \
      ghcr.io/${{ github.repository }}:${{ github.sha }}
```

The important value is:

``` text
${{ github.sha }}
```

GitHub supplies the full commit SHA automatically.

This avoids using only a mutable `latest` tag and creates a direct
relationship between a Git commit and its Docker image.

#### 4. Push the versioned image to GHCR

The following step was added:

``` yaml
- name: Push versioned image to GHCR
  if: github.event_name == 'push' && github.ref == 'refs/heads/main'
  run: |
    docker push \
      ghcr.io/${{ github.repository }}:${{ github.sha }}
```

The image was published to:

``` text
ghcr.io/gaurav-dwivedi-de/data_engineering_portfolio
```

The verified image tag was:

``` text
5d9218b782bc2441aa392d772304073bfb99b15d
```

Therefore the published image reference was:

``` text
ghcr.io/gaurav-dwivedi-de/data_engineering_portfolio:5d9218b782bc2441aa392d772304073bfb99b15d
```

#### 5. Keep the workflow success messages accurate

The final workflow uses separate messages for CI validation and image
publishing:

``` yaml
- name: CI validation successful
  run: echo "P2-W4-D3 CI validation completed successfully"

- name: Image publishing completed
  if: github.event_name == 'push' && github.ref == 'refs/heads/main'
  run: echo "P2-W4-D3 container image published successfully"
```

This prevents a pull-request run from claiming that an image was
published when the GHCR steps are skipped.

### Problems Faced / Decisions

#### Immutable image versioning

The existing environments use:

``` text
airflow-custom:latest
```

A `latest` tag does not identify the exact source revision that produced
an image.

D3 therefore uses the Git commit SHA:

``` text
${{ github.sha }}
```

The verified image is:

``` text
ghcr.io/gaurav-dwivedi-de/data_engineering_portfolio:5d9218b782bc2441aa392d772304073bfb99b15d
```

#### Local and Oracle Kubernetes image state

The local Docker image:

``` text
weather-platform:local
```

is not currently the image referenced by the local Kubernetes
application pods.

Both local Kubernetes and Oracle K3s currently reference:

``` text
airflow-custom:latest
```

This was recorded before changing the deployment model.

#### D3 versus D4

D3 establishes:

``` text
GitHub Actions → GHCR
```

D4 will establish:

``` text
GHCR / GitHub Actions → Oracle K3s
```

The Oracle workloads were deliberately left unchanged during D3.
