#### 2. Added the forecast-to-archive transition

I added `archive_expired_forecasts()` to the archive checking module. It
converts expired forecast records into archive records and removes
expired forecast duplicates while preserving today's forecast records.

**Why I changed it**
The pipeline needs to keep the database state correct as forecast data
becomes historical data. Yesterday's forecast should become archive
data, while the current forecast should remain available for the next
prediction cycle.

**Code Snippet**

``` python
result = archive_expired_forecasts()
```

### Observations

The recovery check should validate the actual archive contents instead
of only checking whether a dataset or database table exists.

I learned that checking dates for each city is important because a
database can contain weather data while still having missing dates for
individual cities.

I also learned that forecast data and archive data need to be treated
differently. Expired forecasts can become archive records, while the
current forecast needs to remain available.
